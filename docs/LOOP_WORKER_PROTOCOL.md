# Worker self-correction loop

Owner direction, 2026-10-10. This protocol governs the active Home assignment
in HOME_004_LOOP_CAMPAIGN.md. It is a work procedure for the owner-relayed
worker, not a scheduled automation or a requirement to use Chat On Steroids.
It supersedes historical checkpoint-only return instructions within this scope.

Lead tidy clarification: use HOME_004_CURRENT_STATUS.md and the compact campaign
as current pointers. Detailed prior rounds stay in linked history/receipts.
Complete the named systematic case pass instead of treating each new permutation
as a new campaign/package. Build one final candidate after ready corrections
settle. An excluded commercial feature is not an included Home acceptance gate;
trace why any missing original dependency matters before calling it blocking.

## Repeat until the assigned acceptance gates pass

1. Read the current queue, actual production path and original authority.
   Select the highest-priority ready gap. Distinguish an implementation defect,
   missing verification, undecoded available source and genuinely absent input.
2. Reproduce the difference through the actual affected boundary. Record the
   symptoms, source locator, hypothesis and counter-evidence. Existing passing
   general tests do not close a failed distinguishing case.
3. Make the smallest source-backed correction. Preserve original observable
   behavior, working features and ownership/restoration protections.
4. Run the distinguishing case and appropriate affected regressions. If they
   fail, inspect the actual failure, revise the hypothesis, fix and retest.
   Try another evidence-supported approach when the first one is disproved.
5. Review the resulting diff for regressions, races, edge cases and unintended
   scope changes. Resolve valid findings and rerun affected checks.
6. When the milestone is coherent, update the compact queue, commit and push
   normally, verify the direct remote SHA, then start the next ready obligation.
   A successful checkpoint is a progress save, not a reason to stop for approval.

Ordinary compile errors, failed tests, stale harnesses, transport failures,
integration defects and failed live observations belong inside this loop.
Do not return AWAITING_REVIEW merely because an attempt failed, a milestone
ended, or an arbitrary amount of time elapsed. Do not ask the owner to relay
another prompt for routine diagnosis or already-assigned continuation.
Brief progress updates are allowed; intermediate updates are not final handoffs.

## Progress and interruptions

Keep one current continuation section in the campaign file: checkpoint SHA,
current obligation, last actual result, next concrete action/command and cleanup
state. Preserve useful failure records separately from corrected proof. Avoid
duplicated evidence archives and a new release ZIP for every small change.
Use sequential medium milestones inside the one campaign. There is no fixed
20-minute stop, overall time target, or prescribed number of retry attempts.

After context compaction or resumption, inspect the checkout and saved
continuation and resume the first incomplete obligation. Do not restart finished
work. A forced session/usage interruption is an interrupted checkpoint, not
completion; leave exact continuation so the same assignment can resume.

## Quality and execution boundaries

Never weaken assertions, rewrite immutable negatives, suppress unexpected errors,
fake readiness/results, invent retries or substitute a different workflow to
make a check green. Repair a stale harness against the actual current boundary
and preserve its historical record. Distinguish controlled proof, genuine
current-client behavior and exact original authority.

Each live retry needs a concrete diagnostic hypothesis, a bounded observation
plan and confirmed restoration from the preceding attempt. Do not blindly repeat
identical faults. Keep identity, isolation, backups and exact-owner cleanup.
An explicit owner pause or actual tool approval denial must not be bypassed.
Continue other authorized ready work when a live step cannot proceed.
No expansion into Map, unrelated gameplay, updater or protected-service access.

## Return boundary

Return once the campaign's whole-Home original-contract and working-package
acceptance gates pass, proposing READY_FOR_LEAD_REVIEW. The lead independently
audits and decides acceptance and merge; the worker never self-approves main.

If completion genuinely requires an unavailable artifact/key/schema, unsupported
client capability or access beyond authorization, investigate legitimate available
alternatives and finish all other ready assigned work first. Then return
PARTIAL_NEEDS_INPUT, naming each affected obligation, exact missing input,
attempted alternatives, preserved negative proof and precise next action.
This is not a successful whole-Home closeout. Do not fabricate the missing
behavior or continue an unproductive idle retry loop.
