## Repeat until the assigned acceptance gates pass

1. Read the current functional queue, actual production path and available original authority.
   Select the highest-priority ready gap. Distinguish an implementation defect,
   missing verification, undecoded available source and genuinely absent input.
2. Reproduce the difference through the actual affected boundary. Record the
   symptoms, source locator, hypothesis and counter-evidence. Existing passing
   general tests do not close a failed distinguishing case.
3. Make the smallest supported correction. Preserve feature purpose, working
   workflows and ownership/restoration. When original detail is unknown, choose
   a documented own-design method and test it; do not wait for irrelevant missing
   original inputs or falsely claim recovery.
4. Run the distinguishing case and appropriate affected regressions. If they
   fail, inspect the actual failure, revise the hypothesis, fix and retest.
   Try another evidence-supported approach when the first one is disproved.
5. Review the resulting diff for regressions, races, edge cases and unintended
   scope changes. Resolve valid findings and rerun affected checks.
6. When the milestone is coherent, update the compact queue, commit and push
   normally, verify the direct remote SHA, then start the next ready obligation.
   A successful checkpoint is a progress save, not a reason to stop for approval.

Ordinary compile errors, failed tests, stale harnesses, transport failures,
integration defects and failed live observations belong inside this loop.
Do not return AWAITING_REVIEW merely because an attempt failed, a milestone
ended, or an arbitrary amount of time elapsed. Do not ask the owner to relay
another prompt for routine diagnosis or already-assigned continuation.
Brief progress updates are allowed; intermediate updates are not final handoffs.
