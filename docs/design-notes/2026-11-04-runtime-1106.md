instead changed all three pinned runtime artifacts, while the four critical Lua anchors remained
identical. The installed app was the correct 62fdcffe build. The earlier repair therefore did
not cover this failure; calling it general future proofing was too broad.

Policy 4 retains the previous supported runtime and adds the exact 1106 game/xlua/assembly tuple.
Both language implementations reject mixed tuples. Critical Lua, package format/CRC, original
entry and exact restore checks remain. Preflight inspects compatibilityOk as well as evidence
and reports GAME_UPDATE_UNSUPPORTED with observed identities/problems before injection.

Static evidence: REA PE resource inventory ev_1eb7946c0bb0215a5ee59fc01942e61c47ccc085b8a7ca366b3d27f0dcfadc26
identifies the new executable. The repository RGMD inspector recovered LuaEnv construction,
DoString and Tick interfaces and WorldPointManager metadata from the new assembly. Metadata
availability is not proof that gameplay behavior is unchanged.

PROVEN: an isolated first-use official settlement followed by genuine Home launch, authenticated
connection and initialization passed on Lua v31. Exact process exit and restoration of the three
post-update originals were audited. All gameplay tasks were disabled, and the owner app was
preserved. Raw receipts and binary identities remain in ignored artifacts/client-1106-20261104.

Controlled validation: full Windows Desktop suite and coherent-runtime negative cases passed;
Python runtime admission and four release packager tests passed. The full Python suite produced
45 passes and nine source-identity failures. Trial admission of v31 showed that several tests
then pass their native assertions, but attack and City checks still reject changed UIUtil and

All gameplay qualification remains UNKNOWN on 1106. This Home fix is not a release qualification.

Future script-only updates can recover within admitted runtime tuples. Future native changes
need explicit inspection and qualification. Automatically adding observed hashes would remove
the compatibility check and cannot be described as future proofing.
