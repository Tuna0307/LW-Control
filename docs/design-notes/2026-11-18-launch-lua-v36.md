# Launch compatibility for official Lua v36

The official launcher installed manifest 1110 and Lua content v36. LW-Control's policy 4
preflight rejected two changed critical Lua entries before the bridge helper started.
The installed LastWar.exe, xlua.dll and Assembly-CSharp.rdl still match the previously
admitted 1106 runtime tuple. The package size and CRC match the official metadata.

Decoding the shipped v31 and v36 LWLF packages and comparing their Lua instructions with
constant and child references resolved shows three added root instructions for
`SAND_WORM_BOOM_STATUS_ID` and two added callback registrations,
`OnBattlePlanWorldPointStatusesChanged` and `CreateBattlePlanSandWormBomb`.
The existing instructions and callback bodies in those two entries match the v31 reference.
The other two critical entries are byte-identical. This comparison covers the four
launch anchors. Separate gameplay modules and gameplay behavior remain unqualified.

Python and Desktop policy 5 recognize the v36 anchor set only with the observed official
package SHA-256, Lua content version 36 and the admitted 1106 runtime hashes. The prior
compatibility branch still checks the existing anchor set. Package CRC and original-file
checks continue in the helper. Controlled tests exercise the exact case and reject changed
package identity, incorrect content version and mixed anchors. The Python test also rejects
the v36 package paired with the older runtime.

The Release build, full Windows Desktop checks, Lua v36 candidate roundtrip, controlled
compatibility checks and packaged Home fixture passed. The full Python suite reports
46 passes and nine failures. The same nine source qualification tests failed before
this change because their expected native package or module identities are older.
