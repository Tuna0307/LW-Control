## 10. R8-099 — decrypted module-table format and exact source assembly

Durable review:

`docs/reviews/2026-09-27-r8-099-module-table.md`

`evidence/lwbridge-implementation/2026-09-27-r8-099-module-table.json`

Reproduction:

`python tools\inspect_lwbridge_proxy_module_table.py ..\LW\lwbridge-0.3.1.exe --json`

Post-AES module-table parser:

`RVA 0x125C0`

Caller from the package/auth function:

`RVA 0x1CC54 -> 0x125C0`

### Exact decrypted plaintext structure

The AES-GCM plaintext is **not** one already-concatenated Lua script.

It is a format-2 module table:

```text
u32_le moduleCount

repeat moduleCount times:
    u32_le nameLength
    u32_le sourceLength
    name[nameLength]
    source[sourceLength]
```

`moduleCount` must be from **1 through 1024 inclusive**.

Per-entry advancement is exactly:

`8 + nameLength + sourceLength`

Allowed module-name bytes are exactly:

`.0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ_abcdefghijklmnopqrstuvwxyz`

Malformed entries trigger exact parser failures including:
- `invalid module table`
- `invalid metadata`
- `invalid entry metadata`
- `invalid entry`

### Special bootstrap module

Module name exactly:

`bootstrap`

is special.

Requirements:
- bootstrap must be present;
- bootstrap source must be non-empty;
- duplicate bootstrap is rejected with `duplicate bootstrap`;
- missing bootstrap is rejected with `bootstrap missing`;
- all decrypted bytes must be consumed exactly;
- extra bytes cause `trailing package data`.

### Exact generated Lua source

The parser starts with exactly:

```lua
local __bridge_preload = package.preload
```

including the trailing newline.

For each non-bootstrap module:

```lua
package.loaded["<name>"] = nil
__bridge_preload["<name>"] = function(...)
<original module source>
end
```

Exact static fragments:

- `local __bridge_preload = package.preload\n`
- `package.loaded["`
- `"] = nil\n`
- `__bridge_preload["`
- `"] = function(...)\n`
- `\nend\n`

After all normal modules, the raw bootstrap source is appended at the end.

Therefore the full protected path is now structurally:

`LWBP2 encrypted package -> AES-GCM plaintext format-2 module table -> exact module splitting -> generated Lua source -> @bridge-scripts.dat compiler -> bytecode -> game xLua`
