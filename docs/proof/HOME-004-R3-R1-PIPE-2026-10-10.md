# HOME-004 R3-R1 — isolated production named-pipe listener correction

The unchanged lead negative result remains in `HOME-004-R3-LEAD-PIPE-INVERSE.json`.
Starting at `dca7cb23465f35e24a882ef1056fa08ad2850c20`, the supplied
`home_004_pipe_idle_probe` recreated `LEADHOME004R3-01`: the first client
authenticated, its production 30-second reader idle cancellation propagated
into the shared accept loop as `OperationCanceledException`, the host still
advertised started, and the successor timed out connecting. **Its exit code 0
was a defect confirmation**.

## Original-source boundary

The verified original `lwbridge-0.3.17.exe` (SHA-256
`4E9C3113DEDFD7E1A752404C6936AAB304E67D7FFDB0952A5003C2EC948D6783`)
contains `PIPE_IDLE_TIMEOUT`, `named pipe received no frames before the activity
timeout`, `PIPE_DISCONNECTED`, `PIPE_FRAME_INVALID` and
`PIPE_HANDSHAKE_TIMEOUT`. Direct local binary-string checks confirm these
**0.3.17 error names** but do not recover the original 0.3.17 exact idle
duration or task/failure-supervision control flow. The current adapter's 30 s
idle duration and queue limits are independently recovered from **0.3.1** in
`LWBridgeControlPipeTransportLimits`; they are not promoted to 0.3.17 facts.

## Correction and independent real-boundary positive

The accepted-session handler now retires its own authenticated route for
session-local idle cancellation, invalid framed/JSON traffic, EOF and pipe I/O
failure, while leaving the **shared** native accept loop alive. Outer host
cancellation still stops the listener. Unexpected non-session/pipe listener
faults remain fatal and are exposed rather than misreported as healthy
idempotent startup. Registration admission, PID/build/canonical executable
verification, generation-scoped route cleanup and original configured limits
remain unchanged.

The new `tools/home_004_pipe_recovery_probe` executes the actual production
Windows named-pipe host, native listener, handshake, route registry and RPC
transport with a unique self-owned inert pipe. Release output:

```
PROBE_PHASE_REJECTIONS_OK
PROBE_PHASE_MALFORMED_OK
PROBE_PHASE_IDLE_OK
PROBE_PHASE_RECONNECT_OK
PROBE_PHASE_RPC_OK
PROBE_PHASE_SHUTDOWN_OK
PROBE_PHASE_PATH_OK
HOME004_R3_R1_ISOLATED_PIPE_RECOVERY_OK
```

Negative admission covers wrong token, wrong reported PID, wrong build, wrong
actual executable image, malformed hello JSON and invalid hello frame length.
An authenticated invalid frame retires only that session. The original valid
client then idles through the **unaltered** 30-second configured timeout;
listener remains active, same-host `EnsureRpcTransportAsync` remains healthy,
and the successor authenticates through a fresh hello/ACK. The probe also
reconnects the same registered instance with a higher route generation and
proves a stale removal cannot retire it. A separate newly registered successor
performs a real framed Lua call/result round-trip. Explicit `host.Close()`
stops the listener and rejects its held RPC as `APP_SHUTTING_DOWN`. The first
native pipe instance flag was used once. No game/launcher was launched and
no original installation, profile or production pipe was touched.

This is **current-client production transport correction** and isolated native
proof, not a claim of authenticated **packaged** real-game hang recovery. The
prior failed R3 live attempt and lead negative receipt remain intact.
