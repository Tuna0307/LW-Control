## LEADMAP006-01: exact Stop before return

- **Cause:** `CancelCycleAndStopOwnedScanAsync` canceled the token and asynchronously held `StopOwnedScanAsync`, while the canceled `RunCycleAsync` independently entered `finally` and returned to origin before that native Stop released its scan lease. The earlier same-origin fix did not apply after a foreign target.
- **Correction:** `RunCycleAsync` owns the sole serialized native Stop, and awaits the *exact captured run* before any requested off-origin return. `CancelAsync` cancels then awaits the entire cycle, not a competing native Stop. Stop rejection only counts as safe when exact same run is confirmed terminal; a successor mismatch is an error, never permission to navigate a successor. Failed Stop suppresses return and persists an explicit error. Retirement never returns on the old/dead owner. Actual return failures remain visible; there are no blind retries or weakened native leases. Return is skipped only when the cycle never attempted another server or the owner retired / native Stop could not establish safety.
