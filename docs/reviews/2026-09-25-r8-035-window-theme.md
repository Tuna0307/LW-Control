## Accepted semantic values

The native window-theme helper accepts exactly:

- `light`
- `dark`

Any other parsed string returns:

- code: `INVALID_THEME`
- message: `theme must be light or dark`

The frontend only invokes this command with its normalized stored theme, which is either `light` or `dark`.

Malformed/missing non-string `theme` fields are rejected by the native Tauri/serde payload layer before the window-theme helper. R8-035 does not claim byte-for-byte parity for that framework-generated malformed-payload text; the retained frontend does not generate that shape.
## Recovered DWM sequence

The helper calls `DwmSetWindowAttribute` four times, in this exact order, with a 4-byte value each:

| Attribute | Meaning | Light | Dark |
| --- | --- | ---: | ---: |
| 20 | immersive dark mode | `0` | `1` |
| 35 | caption color | `0x00FFFFFF` | `0x00282828` |
| 36 | text color | `0x001F1D1D` | `0x00F7F5F5` |
| 34 | border color | `0x00EAE5E5` | `0x003C3A3A` |

Native stops at the first negative HRESULT.
## Failure and success behavior

A failing DWM call returns:

- code: `WINDOW_THEME_FAILED`
- message prefix: `DwmSetWindowAttribute failed: `

The native formatter at VA `0x140039740` formats the 32-bit HRESULT as signed base-10 decimal. For example, `0x80004005` becomes `-2147467259`.

Normal success returns unit/null.

R8-035 applies the recovered sequence to the actual WinForms top-level window handle on the UI command path. The backend's prior `set_window_theme -> null` no-op is bypassed by the desktop host for real UI invocations.
## Regression coverage

`WindowThemeChecks` injects a fake DWM writer and proves:

- dark returns null;
- light returns null;
- exact attribute order 20, 35, 36, 34;
- exact light values;
- exact dark values;
- every value is 4 bytes;
- unsupported semantic theme returns exact `INVALID_THEME` code/message;
- a negative HRESULT returns `WINDOW_THEME_FAILED` with signed-decimal detail;
- processing stops on the first failed DWM attribute.

The deterministic test never changes the user's actual desktop theme.

## Research fences discovered while selecting R8-035

`profile_create` is not a safe local registry mutation: native creation is gated by shared account/profile capacity state and returns `PROFILE_LIMIT_REACHED`; the same subsystem exposes `license_capacity`. The rebuild's fixed single-profile quota must not be substituted for licensed capacity.

`server_jump_history_get`, `server_jump_history_set`, and `server_jump_history_import` all resolve a profile runtime through the native bridge-pipe runtime map. Missing runtime can return `PROFILE_RUNTIME_UNAVAILABLE`. The rebuild's existing local-config set/import path is therefore not yet a proven owner-equivalent implementation; that mismatch is reserved for runtime-owner recovery rather than extended with a synthetic get command.
