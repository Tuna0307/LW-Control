# R8-040 — restore proxy_status public contract

**Date:** 2026-09-26
**Reference:** verified LWBridge 0.3.1
**Scope:** restore the native read-only proxy/install status projection without claiming the still-unrecovered launcher/proxy mutation lifecycle.

## Authority

Primary native evidence:

- `proxy_status` handler RVA `0x15636E-0x156D0A`;
- selected-profile runtime resolver `0x1402AE43C`;
- runtime lookup/error path `0x14041C8AB`;
- launch-component snapshot helper `0x1403A2C27`;
- runtime-managed helper `0x1403A297B`;
- public projector `0x1403A2A66`;
- base proxy-status builder `0x1403E3AB1-0x1403E48A8`;
- proxy path builder `0x1403E37A2-0x1403E3A08`;
- proxy hash/mode helper `0x1403E5B7A-0x1403E5F9A`;
- result serialization helper `0x1402BB816`.

The retained Overview frontend materially consumes `gameRunning` and `repairRequired`. Connectivity remains a separate status path; there is no native-public evidence for the rebuild-only `bridgeOnline`, launcher/PID telemetry fields previously emitted by `proxy_status`.
## Exact public projection

When the selected runtime has a launch component, native builds these fields in this order:

1. `state`
2. `installed`
3. `resourceAvailable`
4. `targetExists`
5. `originalExists`
6. `installedMode`
7. `gameRunning`
8. `targetPath`
9. `runtimeManaged`
10. `repairRequired`

`installedMode` is `"secure"`, `"plain"`, or JSON `null`.

When no launch component is available, native returns the reduced nine-field projection: `installedMode` is omitted, `state="targetMissing"`, `installed=false`, `targetExists=false`, `originalExists=false`, `gameRunning=false`, and `targetPath=""`. `resourceAvailable`, `runtimeManaged`, and `repairRequired` are still projected.

The old rebuild-only fields `launcherRunning`, `bridgeOnline`, `gamePid`, and `launcherPid` are not part of the recovered native public object and have been removed from this command.
## Recovered file/state semantics

The native path builder resolves the target under:

`Game\LastWar_Data\Plugins\x86_64\xlua.dll`

and the preserved original as:

`Game\LastWar_Data\Plugins\x86_64\xlua_.dll`

The same path builder also recovers `xlua-proxy-bundle.json` and the `bridge-runtime\backups` location. The original resource set contains `xlua-proxy-secure.dll`, `xlua-proxy-plain.dll`, and the bundle manifest.

Native state selection is:

- resources unavailable -> `resourceMissing`;
- resources available but target absent -> `targetMissing`;
- target present but original absent -> `needsRepair`;
- target/original/resources present and target matches a recovered proxy mode -> `installed`;
- otherwise -> `needsRepair`.

`installedMode` is `secure` or `plain` only when the target hash matches the corresponding recovered proxy resource; otherwise it is null.
## runtimeManaged and repairRequired

The public projector appends `runtimeManaged` from the runtime ownership helper.

`repairRequired` is not the rebuild's Overview recovery-journal flag. Native sets it true only when all three conditions hold:

- `runtimeManaged == false`;
- `gameRunning == true`;
- `state == "needsRepair"`.

If the runtime is managed, `repairRequired` is false even when the underlying proxy state is `needsRepair`.

The rebuild now derives `runtimeManaged` from actual owned Overview lifecycle state. This is equivalent host plumbing for the recovered public boolean; it does not claim the original multi-instance runtime table implementation.

## Profile/runtime errors

Native `proxy_status` requires a string `profileId`. Static recovery proves the stable codes:

- `PROFILE_ID_REQUIRED`;
- `PROFILE_RUNTIME_UNAVAILABLE`;
- `STATE_UNAVAILABLE`.

R8-040 removes the generic rebuild scope gate from this command so these native handler codes remain observable. No exact native prose message is claimed for the first two codes because the recovered error constructors are code-centric and no dedicated prose strings were found.
## Resource plumbing boundary

The original binary owns its extracted proxy resource set. The rebuild does not yet own the original install/backup/restore lifecycle. For this read-only checkpoint, resource discovery uses an equivalent locator: a complete `xlua-proxy-bundle.json` + secure/plain proxy set beside the app when present, or a complete extracted set under the original `%LOCALAPPDATA%\LastWar-xLua-Bridge\runtime` tree.

Mode classification hashes the actual target and actual recovered resource files; it does not manufacture a mode from a guessed state.

This compatibility plumbing is deliberately read-only. R8-040 does **not** install a proxy, overwrite `xlua.dll`, create `xlua_.dll`, restore backups, launch the game, or claim the original close/exit lifecycle.

## Validation

Deterministic checks cover the exact full and reduced field sets/order, secure/plain/null mode classification, all recovered state outcomes, managed/unmanaged repair projection, exact target/original paths, strict profile/runtime validation codes, and `STATE_UNAVAILABLE`.

The older regression that equated `proxy_status.repairRequired` with the rebuild Overview repair journal was corrected because that coupling is non-native.
