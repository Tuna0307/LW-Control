## Production root cause and fix — `LIVE_PROVEN`

`Map317CommandService` has concurrent current-client world-status consumers: the
scan path and the scheduled Dispatch/Truck worker loops. Before this task,
`CurrentClientMapBlockSource.GetMapStatusContextAsync()` allowed those callers to
share one single-slot protocol pair concurrently:

- `%LOCALAPPDATA%\LWBridgeRebuild\overview-bridge\world-state.txt`;
- `%LOCALAPPDATA%\LWBridgeRebuild\overview-bridge\world-state-result.json`.

Each caller writes a unique request ID and accepts only a correlated result. A
concurrent request can overwrite the single request slot or consume the single
result slot before another caller receives its own correlation. The affected
caller then reaches the existing five-second status-probe timeout, and the public
scan-state path converts that provider exception to
`GAME_CONNECTION_UNAVAILABLE`.

The minimal fix is in:

`src/LWBridge.Desktop/CurrentClientMapBlockSource.StatusState.cs`

It adds a per-source `SemaphoreSlim worldStateGate` around the complete existing
world-state request/write/poll/correlation/validation transaction and releases it
in `finally`. The request/result contract, timeout, validation rules and Map scan
state-machine semantics are otherwise unchanged. No wrapper Lua, server-jump,
restart/resume, auth/licensing, or unrelated gameplay behavior was changed.

Deterministic coverage in
`tests/LWBridge.Desktop.Checks/CurrentClientMapBlockSourceChecks.cs` forces one
world-state request to remain pending while a second attempts to enter. It proves
only one request enters the protocol writer at a time, then proves both requests
complete against their own correlated result. The check is called from the normal
`Program.cs` path after module initialization; it is intentionally not run through
`Task.Run` from the module initializer because that earlier test arrangement hit
CLR type-initialization locking rather than a production defect.

The recovered production stop behavior itself remains `EXACT_CONTRACT`; this
task adds fresh live proof that the current v22 integration satisfies it.
