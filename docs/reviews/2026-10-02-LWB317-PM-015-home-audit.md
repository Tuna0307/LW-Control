## Actionable findings

1. **Home error translation differs.** Original Ir extracts code tokens, including
   tokens embedded in messages, deduplicates them and reverses priority. Lr tries
   `error`, `auth.error`, `update.error`, then localized `common.actionFailed`.
   Clone translatedError checks one `error.*` key and otherwise shows raw text.
   A synthetic unknown action error renders a localized generic message in the
   reference and its raw QA token in the clone. This also affects recovery detail.
   `App.jsx` currently collapses rejected writes to message text before rendering;
   inspect producers within the small correction rather than inventing commands.
2. **Home errors are conflated.** Source root-picker error and action error are
   independent; action error can render outside the picker even with a missing root.
   Clone uses one `homeError` and redirects it into the picker when root is missing.
   A two-error source input cannot be represented faithfully by the current adapter.
   Add distinct display channels in a separate correction while preserving accepted
   reconnect profile scoping, acknowledgement ordering and native gates.
3. **Busy presentation differs.** Source header processing depends on proxyBusy;
   gameRootBusy controls the picker button separately. Clone treats gameRoot busy
   as header processing in a valid-root synthetic case. Source launch button reads
   Processing during proxyBusy, and close button does so only when proxyBusy and
   gameRunning; clone keeps normal labels. Correct display predicates later without
   adding native launch/stop/update providers. Proxy/launch producer reachability
   is still unvalidated; these are recovered contracts, not live regression claims.
4. **Switch descriptions contain English state text in other locales.** Actual
   source Bn translates `common.enabled`/`common.disabled`; clone ToggleRow appends
   literal Enabled/Disabled. Japanese Home displays the translated label followed
   by English Disabled. Shared ToggleRow has other callers, so any later fix must
   verify those callers while preserving existing callbacks/disabled conditions.
