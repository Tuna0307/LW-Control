`game_root_status` every five seconds and handled a successful response with only
the status setter. The exact recovered 0.3.17 source instead requests root status
from the selected-profile effect and routes success through `Jt`, which sets root
status and clears the root error. Its periodic poll contains status/proxy only.

bootstrap profile contract. `selectedProfileId` is `backendBridge.profileId`; the

`gameRootError`. The valid-folder path reuses the same callback after its explicit
status acknowledgement. Failed initial or selection/status requests still write
only the root channel, while action/preference errors remain independent.

map-scan, recovery and local-config refreshes remain present, as do the game
recovery, status and scan listeners and the five-second interval. The server-jump
manual refresh still awaits `refreshStatus`, so it no longer re-reads root status;
root retrieval now occurs on the selected-profile effect and after valid folder
selection.
