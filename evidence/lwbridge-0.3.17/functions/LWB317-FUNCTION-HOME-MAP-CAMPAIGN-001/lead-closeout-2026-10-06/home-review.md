### HCF-01 — Isolated profile-owner proof can delete the real application bridge lease [P1]

`OverviewLifecycleService.cs:107-109` constructs `runtimeRoot` from the real `%LOCALAPPDATA%/LWBridgeRebuild/overview-bridge`, independently of the injected profile/config directory. `Close()` always calls `StopLeaseTimer(deleteLease: true)` at `:403-420`; `StopLeaseTimer` deletes `lease.txt` and all matching temporary leases at `:1433-1446`, without checking whether this lifecycle created or owns them. `DeleteFile` calls `File.Delete` unless a specific test hook exists (`:1596-1599`). A lifecycle that has never launched anything can therefore delete another session's lease.

The packaged offline path `LWBridgeWindow.CreateHomeMapCampaignRuntimeOwner` (`:666-694`) supplies isolated installation/provider/config seams and disables recovery/control-pipe startup, but omits `lifecycleTestHooks` and provides no isolated lifecycle runtime directory. `ProfileRuntimeOwner.Create` passes that null through to the lifecycle (`ProfileRuntimeOwner.cs:139-147`). Profile swaps and final shutdown close those lifecycles (`LWBridgeWindow.cs:557-563`, `:762-775`, `:4408`). `ProfileRuntimeOwnerChecks.CreateOwner` also omits lifecycle hooks (`tests/LWBridge.Desktop.Checks/ProfileRuntimeOwnerChecks.cs:136-171`) and disposes A/B/A owners. This is an actual source side effect, not merely absence of positive game proof.

Required offline correction: place all lifecycle runtime/evidence writes/deletes under explicit isolated roots or supply complete inert hooks, and add a distinguishing sentinel/foreign-lease preservation check. Production deletion also needs exact ownership, because an inactive replacement owner has the same global directory. Do not run an owner-impacting negative repro against the real application root. The reviewer notified the coordinating lead before further proof execution.

The coordinating lead reported seven already-completed focused checks, including the profile-owner check, passed before this warning; further native/desktop execution was then stopped. Post-run inspection found no current lease, but there was no pre-run lease baseline. Consequently this review claims neither that an owner lease was actually deleted nor that owner runtime files were unchanged. The blocker is the proven unisolated filesystem path and unconditional deletion trace.

### HCF-03 — A late older status pair can overwrite a newer failure/disconnection [P1]

`App.readStatusSnapshot` invalidates availability before each read (`App.jsx:559-564`), but its completion check only fences document/effect callback and profile generation (`:575`). It has no status-read revision. Every successful completion installs runtime/proxy state and sets `statusPairReady=true`, `connectionError=""` (`:576-579`, `:594-596`). The Auto Launch config part has its own read generation (`:568-569`, `:581-583`), demonstrating that generation is not applied to the status pair.

Periodic polling serializes only its own calls through an effect-local `inFlight` (`:692-712`). The rendered Refresh control calls `refreshStatus -> readStatusSnapshot` independently (`:600`, `:1188`). Startup completion also calls that read (`:624`). Therefore older connected read A can be deferred, newer read B can reject or return disconnected, then A can complete and erase B's error/revive connected state. Profile generation is unchanged throughout. `connectionState` will trust the overwritten pair (`mapBackend.js:182-190`).

Required: fence all pair acknowledgements/freshness/error changes by the current paired-read owner, or serialize the actual shared read owner without changing the recovered poll interval. Distinguishing mounted/native check: capture old connected results, defer their completion; perform newer rejected and disconnected reads; release old results; assert old results cannot restore online or erase the latest error. Existing sequential packaged cases (`LWBridgeWindow.cs:3312-3378`) do not cover reverse completion.

### HCF-04 — Root picker bypasses the captured request backend across an await [P2]

General request dispatch captures `requestBackend` and `requestProfileGeneration` (`LWBridgeWindow.cs:3958-3959`), but `game_root_select` takes a special path into `SelectGameRootAsync` (`:3961-3962`). That method uses the mutable Window field `backend` again for cancellation/results/saving (`:4032`, `:4042`, `:4050`, `:4065`, `:4069`). Profile swap does not cancel or drain the document request registry; it replaces `backend` at `:537`. The picker has an asynchronous status read before showing the dialog, and an asynchronous selection save afterward. A queued swap can therefore replace A with B before the later closure uses `backend`, causing A's picker request to write B's config/root or return B's cancelled-selection status. The frontend owner check at `App.jsx:860` protects acknowledgement, not that native write.

Required: bind picker status/save/cancel to the request's exact native owner and fail/retire before writes if that owner is obsolete. Prove a deferred picker status/save across A -> B and A -> B -> A using an explicit inert dialog seam. Preserve cancellation, weak public selection and strict launch admission. This is a source trace, not an executed dialog repro.
