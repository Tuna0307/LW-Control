## MR-01 — injected scan boundary retains its lease after Stop/completion

**P1 acceptance blocker; source-confirmed injected-composition defect, not a claim that the normal current-client provider fails to release its lease.**

`Map317CommandService` holds `activeScanLease` after every admitted Start (`src/LWBridge.Desktop/Map317CommandService.cs:460-473`). Normal composition subscribes `CurrentClientMap317ScanProvider.RunTerminated` to `ReleaseScanLease` (`:60`); the real provider invokes this after engine termination (`CurrentClientMap317ScanProvider.cs:239-250`).

The injected constructor instead sets `scanProvider=null` (`Map317CommandService.cs:93-96`), subscribes only control/action/worker events (`:107-112`), and accepts an `IMapProvider` with no activation, capture-sink, terminal-run or disposal contract. Normal Stop directly calls `control.StopScanAsync` (`:256-257`), and owned Auto Stop does likewise (`:230`). Neither path releases the lease. Lease release occurs only in explicit failed-Start catches, normal concrete-provider termination, or service disposal (`:187`, `:439-440`, `:501`, `:588-597`).

Concrete inert interleaving through the public native service boundary:

1. Inject an adapter that admits one run and returns normally from Stop (the existing controlled provider does exactly this at `MapAutoScanCommandServiceChecks.cs:906-921`).
2. Invoke `map_scan_start`: state is reading and `activeScanLease` is owned.
3. Invoke `map_scan_stop`, or disable Auto: the state machine cancels the durable run, calls provider Stop and becomes idle (`MapScanStateMachine.cs:355-403`). The injected adapter has no terminal event to release `activeScanLease`.
4. Invoke another Start: `TryAcquire` cannot obtain the held file lock and native Start rejects `SCAN_RUNNING` (`Map317CommandService.cs:462-464`) despite idle status. Auto cannot start a later cycle; return movement also rejects while the lease remains held.

Completion is similarly not exposed through this injection contract. The supposedly real native replacement test manually reads the private `control`, invokes `CompleteScan`, then invokes private `ReleaseScanLease` through reflection (`MapAutoScanCommandServiceChecks.cs:850-868`, called at `:545`). That proves stop-if-owned after a prepared replacement, not that the actual injected lifecycle produces completion/lease release. The packaged driver starts and cancels one inert run (`LWBridgeWindow.cs:3255-3293`); it never re-enables/starts another run on the same service to distinguish this fault.

Required offline correction/proof: expose an explicit run-scoped provider execution/terminal boundary or equivalent real service lifecycle seam, with capture/progress/publication/failure and termination ownership. Exercise Start -> Stop -> Start, actual completion -> next target, failed completion -> later cycle, return, disable, timeout, retirement and disposal on the same injected native service. Do not release the lease merely on `IsReading=false` while a real provider task can still be executing, or grant a replacement run admission before that task terminates. Keep private manipulation as a narrowly labeled prepared-state test, not end-to-end production-equivalent acquisition evidence.

## MR-02 — failed lease initialization can leak the opened exclusive file

**P2 source-confirmed resource-cleanup defect; conditional I/O failure, not reproduced by this read-only review.**

`src/LWBridge.Desktop/Map317ScanProcessLease.cs:17-28` creates an exclusive `FileStream`, then truncates/writes/flushes its metadata before returning the owner wrapper. If `SetLength`, writer flush/disposal, or `Flush(flushToDisk:true)` throws after the stream opens, the catch returns null or throws an error (`:30-39`) without disposing the local stream. The writer explicitly uses `leaveOpen:true`. Until finalization releases it, that abandoned exclusive stream can deny a subsequent otherwise valid scan start; an I/O error is also reported as ordinary occupied-owner `SCAN_RUNNING` by callers.

The existing lease check only verifies two successful acquisitions separated by Dispose (`tests/LWBridge.Desktop.Checks/Map317RestartChecks.cs:16-23`). Add exception-safe ownership transfer: retain the stream in a local disposed on every failed initialization, transferring it only after success. Distinguish a real contended file from initialization failure where feasible. Fault-injected initialization failure should prove immediate reacquisition and truthful error reporting; no real disk/game corruption is necessary.
