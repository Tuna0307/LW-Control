## Specific still-available recoveries — not an external blocker

The 0.3.17 shared `0x1D5009–0x1DDBB2` native async body has 6,242 decoded instructions (and 664 direct calls). The R1 short callees and B's precise producers/consumers are only part of its states. The 5s window's returned-record producer `0x2A2887`, the pipe registry's return/error paths `0x2C75CA/0x2C6A65→0x1DD4FD/0x1DD6B5`, continuation `0x1D420D` and indirect waker polls remain traceable in available bytes. **Exact 0.3.17 automatic reconnection classification, 30/60/180s health thresholds, 15/30/60/120/300s normal retries, 120/300/600s maintenance retries, cap indexing and successful-reset rules have NOT been derived from this reference.** Those values come from the *0.3.1* recovery table in `OverviewRecoveryPolicy.cs`, an old hypothesis, not parity acceptance. Native observed 5s/90s waits must not be mistaken for automatic recovery backoff.

The protected original signed-envelope/CNG service/Map controller outputs are a **different** missing-input dependency; none of the 0.3.17 native bytes enumerated here is missing. Missing original post-auth execution limits direct runtime equivalence but does not excuse unfinished static decode.
